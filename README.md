# ChargeScope v3.3

ChargeScope is a static, privacy-friendly **charging-speed explorer** for phones and tablets. Browse devices, inspect manufacturer-sourced charging specifications, estimate a partial/full charging session, compare charger ratings, and optionally record your own measured charging tests.

> **Important:** Estimated times are generated by a generic tapering simulation. They are **not** independently measured charging benchmarks. Quoted adapter requirements are **not** necessarily the maximum power a phone accepts.

## Run locally

Serve this directory over localhost (for example `python3 -m http.server 4173`) and open `http://localhost:4173`. The site is dependency-free at runtime. On HTTPS or localhost, its service worker can provide offline access after the app has been cached.

## What's new in v3.3 — Phone-first quality of life

- **Find any phone instantly:** a searchable, keyboard-accessible device picker with tokens, relevance ranking, favorite priority and a `/` or Ctrl/Command+K shortcut.
- **Recent phones:** up to six locally remembered models with one-tap shortcuts and a clear-history control.
- **Remember your setup:** stores last selected device, charger wattage, charging method/protocol assumption, conditions, and battery range in browser storage. Validates restored values and falls back when a model is gone.
- **Mobile dock:** touch-friendly shortcuts to Estimate, Plan, Phones, and personal Tests, including safe-area padding for gesture navigation.
- **Explained charging limits:** highlights whether the phone, charger/pad, or cable is the selected power bottleneck, and reinforces that a rated wattage is not constant or guaranteed power.
- **Smarter brand changes:** prefers a model with usable published charging data.
- **Polished responsive UI:** improved phone search, result interpretation, controls, text rhythm, and dark/light styling without external trackers or runtime dependencies.
- **Regression protection:** focused unit tests and desktop, Android, iPhone, and tablet Playwright scenarios.

Local preferences and search history do not sync across devices, and clearing browser data removes them. Charging times remain illustrative simulations, not measured device-specific charge curves.

## Data policy and how to extend the database

The directory is manually curated and does **not** claim to cover every global/regional phone. It is **not live-synchronized** with manufacturers.

- `catalog-directory.mjs`: phone names and release years; charging limits are intentionally null unless independently sourced.
- `official-specs.mjs`: manufacturer-backed per-model overlays. Every entry must cite a manufacturer URL, checked date, territory, and state precisely what a charger/adaptor rating represents.
- `devices.mjs`: preserves public IDs and merges official evidence over the directory. Legacy unsourced example wattages are not published as official specifications.
- `catalog-utils.mjs`: trustworthy completeness/status calculation, sorting and filtering.
- `spec-view.mjs`: source inspector and accessible specification sheet.

Only use `wiredW` when a manufacturer describes actual maximum **device charging support**. Use `chargerRecommendationW` instead if a manufacturer merely says “use a 30W/45W/60W adapter” for its own 0–50% timing claim. An unknown wireless capability remains `null`, while **explicitly unsupported** wireless charging can be represented by zero when a manufacturer confirms it. Do not infer a max input from a charger or infer a benchmark from model parameters.

Manufacturers' regional editions, cables, charging protocols, firmware, temperature and battery protection matter. The generic model assumes an illustrative battery voltage when exact pack energy is unknown.

## Other features

- Wired / wireless power model with charger and cable caps, heat/activity inputs, 0–100% or any partial percentage range.
- Interactive simulated charge curve, 3-phone comparison, modeled charger sweet spot, charge milestone clock-time planner.
- Electricity cost estimator with editable tariff and frequency (assumed wall-to-battery efficiency).
- User-created phone profiles, copyable estimate links and personal JSON charge-session history.
- Two or more **matching real measurements** can generate a conservative, bounded local calibration. Personal history is held in browser storage, not sent to a server.
- Installable offline-capable PWA, theme toggle, responsive design and accessibility improvements.

## Testing and deployment

```bash
npm install
node --test tests/*.test.mjs
npm run test:ui
```

The GitHub Actions workflow additionally runs JS syntax checks, installs Chromium and WebKit for Playwright, tests desktop Chrome, Android Chrome, iPhone Safari and tablet Safari, and deploys to GitHub Pages **only after the checks pass**.
